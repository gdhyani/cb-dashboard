---
title: Paths
description: Where cb keeps its local files on macOS, Linux and Windows.
---

The `cb` CLI and the background agent keep a few files in one folder in your home directory. None of them
holds a real secret: the device token sits in your OS keychain, and everything else is IDs, ports and
[stand-in values](/docs/overview/concepts#stand-in-values). Set `CB_HOME` to move the whole folder.

## Home folder

<Tabs items={["macOS", "Linux", "Windows"]}>
<Tab value="macOS">
```text
~/.cb/
```
</Tab>
<Tab value="Linux">
```text
~/.cb/
```
</Tab>
<Tab value="Windows">
```text
%USERPROFILE%\.cb\
```
</Tab>
</Tabs>

All paths below are relative to this folder. When `CB_HOME` is set, it replaces the folder, and that home gets
its own background agent and its own keychain entry.

## Files

| Item | macOS and Linux | Windows | What it holds |
|---|---|---|---|
| Credentials | `~/.cb/credentials.json` | `%USERPROFILE%\.cb\credentials.json` | For each server: your user, the device ID and name, and where the token is stored. Holds the token only when no keychain is available. |
| Snapshots | `~/.cb/run/<projectId>.<environment>.json` | `%USERPROFILE%\.cb\run\<projectId>.<environment>.json` | The environment your app sees, written by the agent and read by the preload. |
| State | `~/.cb/state.json` | `%USERPROFILE%\.cb\state.json` | The local port assigned to each brokered connection, and your default environment per project (`cb env use`). |
| Agent log | `~/.cb/logs/agent.log` | `%USERPROFILE%\.cb\logs\agent.log` | One line per agent event, with tokens redacted. Rotated to `agent.log.1` past 5 MB. |
| Fake key files | `~/.cb/fake/<projectId>.<environment>/<KEY>.json` | `%USERPROFILE%\.cb\fake\<projectId>.<environment>\<KEY>.json` | Stand-in key files for SDKs that read a key from a file, such as `GOOGLE_APPLICATION_CREDENTIALS`. The variable points at the file. |
| Agent control | `~/.cb/agent.sock` | `\\.\pipe\cb-agent-<user>-<id>` | The socket (named pipe on Windows) that the CLI uses to talk to the background agent. |

On macOS and Linux, if the socket path would be too long, the agent uses `cb-agent-<id>.sock` in the system
temp folder instead.

The snapshot contains no real secrets, except values an admin marked as shown as-is. A snapshot looks like
this:

```json title="~/.cb/run/665f1c418a4b3d0012ab34d1.development.json"
{
  "schema": 1,
  "version": 13,
  "status": "active",
  "projectId": "665f1c418a4b3d0012ab34d1",
  "environment": "development",
```

## Device token

[`cb login`](/docs/reference/cli#cb-login) stores the device token in the OS keychain, one entry per cb home
and server:

| OS | Store |
|---|---|
| macOS | Keychain |
| Linux | Secret Service (for example GNOME Keyring) |
| Windows | Credential Manager |

If no keychain is available, or `CB_CREDENTIAL_STORE=file` is set, the token is stored in `credentials.json`
instead. On macOS and Linux the file is readable only by you (mode `0600`); on Windows it relies on your user
folder's permissions. [`cb doctor`](/docs/reference/cli#cb-doctor) warns when the file store is in use.

## File permissions

| Path | Mode on macOS and Linux |
|---|---|
| `credentials.json` | `0600` |
| `fake/<projectId>.<environment>/` | `0700` |
| Fake key files | `0600` |
| `logs/` | `0700` |
| `logs/agent.log` | `0600` |
| `token.lock` | `0600` |
| `agent.sock` | `0600` |

## In your project

| Path | Committed | What it holds |
|---|---|---|
| `.cb/project.json` | Yes | The link to your cb project. See [.cb/project.json](/docs/reference/project-json). |
| `.cb/env.d.ts` | Your choice | Variable names for TypeScript, generated by [`cb types`](/docs/reference/cli#cb-types). |
