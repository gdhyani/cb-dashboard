---
title: .cb/project.json
description: The file that links a folder to a cb project and environment.
---

`.cb/project.json` links a folder to a cb [project](/docs/overview/concepts#project). [`cb init`](/docs/reference/cli#cb-init)
writes it, and every other command finds it by walking up from the current folder. It holds IDs and URLs
only, never a secret, so you commit it and everyone on the team runs against the same project.

## Example

```json title=".cb/project.json"
{
  "server": "http://localhost:4200",
  "orgId": "665f1c2e8a4b3d0012ab34cd",
  "projectId": "665f1c418a4b3d0012ab34d1",
  "projectSlug": "shop",
  "defaultEnvironment": "development"
}
```

## Fields

| Field | Type | Required | What it does |
|---|---|---|---|
| `server` | URL | Yes | The cb backend this project lives on. Used when neither `--server` nor `CB_SERVER_URL` is set. |
| `orgId` | string | Yes | The [organization](/docs/overview/concepts#organization) that owns the project. |
| `projectId` | string | Yes | The project this folder runs against. |
| `projectSlug` | string | No | The project's short name, shown in CLI output instead of the ID. |
| `defaultEnvironment` | string | Yes | The [environment](/docs/overview/concepts#environment) used when you pass no `--env` and haven't set one with `cb env use`. |
| `webhookPort` | integer, 1–65535 | No | Local port that [webhooks](/docs/guides/webhooks/how-it-works) are delivered to. Set it when your app's port can't be detected. `cb run --webhook-port` overrides it. |

`cb init` writes every field except `webhookPort`, which you add by hand when you need it.

## Choosing an environment

The file sets the team-wide default. Each developer can choose a different environment without editing the
file:

- `cb env use <name>` stores a personal default on your machine, in `~/.cb/state.json`.
- `--env <name>` on `cb run`, `cb shell` and the other commands applies to that one command.

See [Environments](/docs/guides/develop/environments).

<Callout type="note">
  The `.cb/` folder can also hold `env.d.ts`, generated by [`cb types`](/docs/reference/cli#cb-types). Don't
  edit it by hand; re-run `cb types` after variables change.
</Callout>
