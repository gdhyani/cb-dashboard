---
title: Preload and explicit API
description: How cb gets values into your app automatically, and the optional typed API for reading them.
---

cb gets its values into your app in two ways. The **preload** runs automatically under `cb run` and needs no code.
The **explicit API**, `import { env } from "@cb/env"`, is optional: it gives you typed access to the same values.
This page explains both and when to use which.

## The preload

`cb run` adds the preload (`@cb/env/register`) to `NODE_OPTIONS`, so Node loads it before any of your code. Child
processes and worker threads inherit it too. The preload:

- Reads the snapshot the agent wrote for your environment. It never fetches anything over the network.
- Sets `process.env` from the snapshot, except keys `cb run` already set.
- Redirects connections to the hosts cb brokers (for example `api.stripe.com:443`) to the local agent, for
  `net`, `tls`, `http`, `https`, HTTP/2 and the global `fetch`. Every other host is left alone.
- Keeps TLS certificate verification on. Redirected connections still check the certificate for the original host.

Your SDKs stay unchanged. `new Stripe(process.env.STRIPE_SECRET_KEY)` or `new PrismaClient()` work as they would
with real values, because the connection, not the code, is what cb changes.

### Fail closed

If the snapshot is missing, or your access was revoked, the preload stops your app before any of your code runs:

```text
cb: access revoked by admin (reason: "…"). Your app was not given any real credentials.
```

If you start a Node process with the preload but without `cb run`, it stops with:

```text
cb: this process wasn't started with "cb run". Use "npm run dev" (scripts are wired by "cb init") or "cb shell".
```

## The explicit API

```ts title="lib/stripe.ts"
import Stripe from "stripe";
import { env } from "@cb/env";

export const stripe = new Stripe(env.STRIPE_SECRET_KEY);
```

`env.NAME` and `env.get(name)` are synchronous and return exactly `process.env[name]`. They hold no values of
their own, so there is nothing secret in them.

| Call | Under `cb run`, when the key is missing | Outside `cb run` |
|---|---|---|
| `env.NAME` | Throws an error naming the key and where to add it in the dashboard | Returns `process.env.NAME` (may be `undefined`) |
| `env.get("NAME")` | Returns `undefined`, never throws | Returns `process.env.NAME` |

`env` is read-only. Assigning to it throws: change values in the dashboard instead.

<Callout type="warning" title="Server code only">
`@cb/env` is server-only. Importing it in browser code fails the build in Next.js, and throws
`@cb/env is server-only` in other bundlers. Keep it in API routes, server components and backend code.
</Callout>

## Types with cb types

Run `cb types` to generate `.cb/env.d.ts` with your environment's variable names:

```bash
cb types
```

```ts title=".cb/env.d.ts"
// Generated by `cb types` for shop-api / development. Do not edit; re-run `cb types` after variables change.
// Names only — values are delivered at run time by `cb run`.
export {};

declare module "@cb/env" {
  interface CbEnv {
    readonly DATABASE_URL: string;
    readonly STRIPE_SECRET_KEY: string;
  }
}

declare global {
  namespace NodeJS {
    interface ProcessEnv {
      readonly DATABASE_URL: string;
      readonly STRIPE_SECRET_KEY: string;
    }
  }
}
```

The file holds names only, never values. It types both `env.NAME` and `process.env.NAME`, so a typo in a key name
fails at compile time. TypeScript skips folders that start with a dot when it expands `include` patterns, so add
the file to your `tsconfig.json` explicitly:

```json title="tsconfig.json"
{
  "include": ["src/**/*.ts", ".cb/env.d.ts"]
}
```

Run `cb types` again after an admin adds or renames a variable. It takes `--env <name>`, and `--json` prints the
names instead of writing the file.

## When to use which

<Callout type="tip" title="Start with process.env">
Keep reading `process.env` as you do today: the preload makes it work with no changes, and your code stays free of
cb. Reach for `import { env } from "@cb/env"` when you want a clear error for a missing key, or typed key names
in a TypeScript project. Both read the same values.
</Callout>
