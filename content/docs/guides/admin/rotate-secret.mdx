---
title: Rotate a secret
description: Replace a real credential in one place, tested before it is stored, without touching developers' code or machines.
---

Rotating a secret with cb is one step: you replace the value in the dashboard, and every developer's app uses the
new one. Nobody updates a `.env` file, and nothing changes in the code, because apps only ever see
[stand-in values](/docs/overview/concepts#stand-in-values), and those stay the same. This guide is for owners and
admins.

## When to rotate

- The provider asks you to, or the key is about to expire.
- Someone with access to the provider's console leaves.
- You suspect the real value leaked from somewhere outside cb.

## Replace the value

<Steps>
<Step>
### Create the new credential at the provider

Create a new key, password or client secret in the provider's console. Keep the old one active for now.
</Step>
<Step>
### Open Replace value

On the environment's **Variables** tab, open the main key's "…" menu and choose **Replace value**. The Edit dialog
opens ready for the new value. You can also open the key, choose **Edit**, then **Replace value**.
</Step>
<Step>
### Paste the new value

Paste it into the field marked **(new value)**, for example **Connection URL (new value)** or
**API key (new value)**.
</Step>
<Step>
### Save

Select **Save**. cb tests the new value from its gateway before storing it. If the test fails, the dialog shows the
error and the old value stays in place.
</Step>
<Step>
### Revoke the old credential

Once saved, revoke the old credential at the provider.
</Step>
</Steps>

After saving, the hidden value shows when it was set, for example "set just now". New connections use the new
value. Developers don't restart anything by hand and don't change any code.

<Callout type="note" title="The old value is gone">
cb keeps only the current value, encrypted on its server. Nobody can read either value back from the dashboard.
</Callout>

## Other things you can replace

| What | Where |
|---|---|
| A second, read-only login | Edit → **Read-only login** (databases) or **Restricted key** (Stripe) → **Replace** |
| A **Secret shown as-is** value | Edit → **Replace value**. There is no connection to test for it, and the value reaches developers' apps directly. |
| A service's address | Edit → change the URL or endpoint. A new address needs the key again, so the old key is never sent anywhere new. |

<Callout type="tip" title="Test without changing anything">
To check that the current value still works, choose **Test connection** in the key's "…" menu. It runs the same test
from the gateway without saving anything.
</Callout>

See [Variables](/docs/guides/dashboard/variables#edit-a-variable) for everything the Edit dialog can do.
