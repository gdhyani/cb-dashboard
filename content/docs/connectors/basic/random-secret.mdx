---
title: Random secret
description: A secret cb generates for each developer, for keys your app invents such as AUTH_SECRET or JWT_SECRET.
---

Some secrets don't come from a provider: your app makes them up to sign sessions, cookies or tokens. A random
secret gives each developer their own value, generated by cb, so there is nothing to paste and nothing shared
between people. Use it for keys like `AUTH_SECRET`, `JWT_SECRET` or `SESSION_SECRET`.

## Before you start

- You are an owner or admin of the organization.
- You know the key name your code reads and the format it expects (most libraries accept any long random string).

## Add it in the dashboard

<Steps>
<Step>
### Open the Variables tab

Open your project, pick the environment, and go to the [Variables tab](/docs/guides/dashboard/variables). You can
click **Random secret** in the **Quick add** row to open the dialog with the type already set.
</Step>
<Step>
### Fill in the dialog

The dialog is titled **Add random secret**. Type the **Key** and pick a **Format**. There is no value to paste:
"Nothing to paste. Each developer gets their own value."
</Step>
<Step>
### Save

Click **Save**. The table shows "generated for each developer" and the format.
</Step>
</Steps>

  <Field name="Format" type="select" required default="base64:32">
    The shape of the generated value. You can change it later in the variable's **Edit** dialog.
  </Field>

<Fields title="Optional (Advanced)" collapsible>
  <Field name="None">
    A random secret has no extra settings.
  </Field>
</Fields>

| Format | What you get |
|---|---|
| `hex:32` | 32 hex characters (16 random bytes) |
| `hex:64` | 64 hex characters (32 random bytes) |
| `base64:32` | 32 random bytes, base64-encoded |
| `base64url:32` | 32 random bytes, base64url-encoded (URL-safe) |
| `alnum:32` | 32 letters and digits |
| `alnum:48` | 48 letters and digits |
| `uuid` | A version 4 UUID |

<Callout type="tip" title="Match the format to your library">
  Pick the format your library documents. A key that must be 32 bytes written as hex fits `hex:64`; a key that only
  needs to be long and random fits the default `base64:32`.
</Callout>

## What your app sees

Each developer gets a different value. It stays the same for that developer in that environment, on every device
and every run, so sessions and tokens keep working after a restart.

## Use it in code

Your code reads the variable as usual.

```ts title="src/auth.ts"
import jwt from "jsonwebtoken";

export const sign = (userId: string) =>
  jwt.sign({ sub: userId }, process.env.JWT_SECRET as string, { expiresIn: "1h" });
```

## Run it

```bash
npx cb run -- npm run dev
```

To see your own generated value, print the environment:

```bash
npx cb env print
```

## Limits

- Values differ per developer. Anything signed with one developer's secret (a cookie, a token) is not valid on
  another developer's machine.
- The value is generated by cb; you can't set it to a specific value. If your app needs one shared value from
  outside, it is not a random secret.

## Troubleshooting

| Problem | Fix |
|---|---|
| The library rejects the secret's length or encoding | Edit the variable and pick a different **Format**, for example `hex:64` for a 32-byte key written as hex. |
| A token from a teammate doesn't verify on your machine | Expected: each developer has their own value. Create the token on your own machine. |
