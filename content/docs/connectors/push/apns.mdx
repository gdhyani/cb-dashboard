---
title: Apple Push (APNs)
description: Send iOS push notifications with node-apn or apns2 using a stand-in .p8 key instead of your real Apple key.
status: beta
---

Store your Apple Push Notification service key (`.p8`) in cb once. Every developer's app gets a stand-in `.p8`
key made for that device, plus the real key ID and team ID. Your push library signs its provider token with the
stand-in key; the cb gateway checks that signature, replaces the token with one signed by the real key, and
forwards the push to Apple over HTTP/2.

## Before you start

- You are an owner or admin of the organization.
- You have an APNs authentication key from **Apple Developer → Certificates, Identifiers & Profiles → Keys**: the
  `.p8` file and its 10-character **Key ID**.
- You know your 10-character **Team ID** (shown under Membership in your Apple Developer account).
- Developers who will run the app have [access](/docs/guides/dashboard/access) to the environment.

## Add it in the dashboard

<Steps>
<Step>
### Open the Variables tab

Open your project, pick the environment, and go to the [Variables tab](/docs/guides/dashboard/variables). Click
**Add variable** and set **What is this?** to **Apple push key**. The dialog is titled **Add Apple push variable**.
</Step>
<Step>
### Name the key and add the .p8

Type the **Key** your code reads, for example `APNS_KEY`, and drop the `.p8` file on **.p8 key** (or choose it, or
paste its full contents, from
`-----BEGIN PRIVATE KEY-----` to `-----END PRIVATE KEY-----`). A wrong file is refused with the reason, for example
"This is a certificate, not an Apple .p8 key."
</Step>
<Step>
### Enter the key ID and team ID

Fill in **Key ID** and **Team ID**. To hand them to your app too, open **Suggested extra keys** and tick
`APNS_KEY_ID` and `APNS_TEAM_ID`.
</Step>
<Step>
### Save & test

Click **Save & test**. cb signs a provider token with the real key and sends a test push for a dummy device to
Apple's sandbox. Apple refusing the dummy device but accepting the token counts as a pass; a rejected key fails, and
nothing is saved.
</Step>
</Steps>

The key ID and team ID are the real ones: they are identifiers, not secrets. The stand-in key is an EC P-256 key,
like a real `.p8`.

## Use it in code

Pass the key from the environment as a string. Both libraries accept PEM text.

<Tabs items={["node-apn", "apns2"]}>
<Tab value="node-apn">
```ts title="lib/push.ts"
import apn from "@parse/node-apn";

const provider = new apn.Provider({
  token: {
    key: process.env.APNS_KEY!,
    keyId: process.env.APNS_KEY_ID!,
    teamId: process.env.APNS_TEAM_ID!,
  },
  production: false,
});

const note = new apn.Notification({ alert: "Your order shipped", topic: "com.acme.shop" });
const result = await provider.send(note, deviceToken);
console.log(result.sent.length, result.failed);
```
</Tab>
<Tab value="apns2">
```ts title="lib/push.ts"
import { ApnsClient, Notification } from "apns2";

const apns = new ApnsClient({
  team: process.env.APNS_TEAM_ID!,
  keyId: process.env.APNS_KEY_ID!,
  signingKey: process.env.APNS_KEY!,
  defaultTopic: "com.acme.shop",
  host: "api.sandbox.push.apple.com",
});

await apns.send(new Notification(deviceToken, { alert: "Your order shipped" }));
```
</Tab>
</Tabs>

## Run it

```bash
npx cb run -- npm run dev
```

If you ran `cb init`, your package scripts already run under cb. To see the stand-in values, run
`npx cb env print`. See [cb run](/docs/guides/develop/cb-run).

## Limits

- Calls must come from a process started by `cb run`. cb catches `api.push.apple.com` and
  `api.sandbox.push.apple.com` by host.
- Token-based authentication (`.p8`) only. Certificate-based APNs (`.p12`) is not supported.
- The key reaches your app as PEM text in an environment variable, not as a file on disk.
- The provider token must carry the saved key ID and team ID.

## Troubleshooting

| Problem | Fix |
|---|---|
| **Save & test** says "Apple rejected the key (InvalidProviderToken)" | The `.p8`, key ID and team ID don't belong together, or the key was revoked. Check all three in your Apple Developer account. |
| "This isn't an Apple .p8 key (-----BEGIN PRIVATE KEY-----)." or "must be a PEM private key" | Drop the `.p8` file itself, or paste the whole file contents including the `BEGIN` and `END` lines. |
| "This is a certificate, not an Apple .p8 key." | You chose a certificate. Download the key (`AuthKey_<KeyID>.p8`) from **Certificates, Identifiers & Profiles → Keys**. |
| "10-character key ID from Apple" or "10-character team ID from Apple" | Use the 10 capital letters and digits Apple shows. |
| Pushes fail with `403 InvalidProviderToken` from cb | The app signed with a key that isn't this device's stand-in (for example a real `.p8` file on disk), or with a different key ID or team ID. Read all three from the environment. |
| `BadDeviceToken` | The device token belongs to the other APNs environment. Use `production: false` (sandbox) for development builds. |

More fixes are in [Troubleshooting](/docs/guides/troubleshooting).
