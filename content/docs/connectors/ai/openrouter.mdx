---
title: OpenRouter
description: Call OpenRouter through the OpenAI or Anthropic SDK while the real OpenRouter key stays on the cb server.
---

Store your real OpenRouter key in cb once. Every developer's app gets a stand-in key that starts with `sk-or-cb-`,
and the cb gateway swaps in the real key on the way to `openrouter.ai`. OpenRouter speaks the OpenAI API, so the
official `openai` SDK works unchanged, including streaming. The official Anthropic SDK works too, through
OpenRouter's Anthropic-compatible API. Both are verified end to end with real OpenRouter.

## Before you start

- You are an owner or admin of the organization.
- You have a real OpenRouter API key (`sk-or-…`).
- Developers who will run the app have [access](/docs/guides/dashboard/access) to the environment.

## Add it in the dashboard

<Steps>
<Step>
### Open the Variables tab

Open your project, pick the environment, and go to the [Variables tab](/docs/guides/dashboard/variables). Click
**Add variable**, set **What is this?** to **AI API key** and **Provider** to **OpenRouter**. The dialog is titled
**Add AI variable**.
</Step>
<Step>
### Name the key and paste the real value

Type the **Key** your code reads, usually `OPENROUTER_API_KEY`, and paste the real key into **API key**.
</Step>
<Step>
### Add the base URL key if your code reads one

**Suggested extra keys** offers `OPENROUTER_BASE_URL`. Its value ends in `/api/v1`, the base the OpenAI SDK
expects for OpenRouter. Without it, cb catches calls to `openrouter.ai` from processes started with `cb run`.
</Step>
<Step>
### Save & test

Click **Save & test**. cb calls `GET /api/v1/key` with the real key from its server before saving. If OpenRouter
rejects the key, nothing is saved and the dialog shows the error.
</Step>
</Steps>

<Fields title="Required">
  <Field name="Key" type="text" required>
    The name your code reads, for example `OPENROUTER_API_KEY`. cb never names it for you.
  </Field>
  <Field name="What is this?" type="select" required default="AI API key">
    The variable type.
  </Field>
  <Field name="Provider" type="select" required>
    Choose **OpenRouter**.
  </Field>
  <Field name="API key" type="secret" required>
    The real key, such as `sk-or-…`. Write-only: nobody can view it after saving, but you can replace it.
  </Field>
</Fields>

<Fields title="Optional (Advanced)" collapsible>
  <Field name="Different endpoint" type="text">
    A company proxy or another endpoint instead of `https://openrouter.ai`. Must be `https://`. When you set it,
    have your app use the base URL key so its calls reach cb.
  </Field>
  <Field name="Extra headers" type="multiline">
    Non-secret headers sent on every call, one `Name: value` per line, at most 10. OpenRouter's optional
    `HTTP-Referer` and `X-Title` attribution headers fit here. Not for keys.
  </Field>
</Fields>

## Use it in code

<Tabs items={["Chat", "Streaming", "Anthropic SDK"]}>
<Tab value="Chat">
```ts title="lib/ai.ts"
import OpenAI from "openai";

const openrouter = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: process.env.OPENROUTER_BASE_URL ?? "https://openrouter.ai/api/v1",
});

const completion = await openrouter.chat.completions.create({
  model: "openai/gpt-4o-mini",
  messages: [{ role: "user", content: "Say hello" }],
});
console.log(completion.choices[0]?.message.content);
```
</Tab>
<Tab value="Streaming">
```ts title="lib/ai-stream.ts"
import OpenAI from "openai";

const openrouter = new OpenAI({
  apiKey: process.env.OPENROUTER_API_KEY,
  baseURL: process.env.OPENROUTER_BASE_URL ?? "https://openrouter.ai/api/v1",
});

const stream = await openrouter.chat.completions.create({
  model: "openai/gpt-4o-mini",
  messages: [{ role: "user", content: "Write a haiku" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}
```
</Tab>
<Tab value="Anthropic SDK">
```ts title="lib/ai-anthropic.ts"
import Anthropic from "@anthropic-ai/sdk";

// authToken sends the stand-in as Authorization: Bearer; apiKey: null stops the SDK reading ANTHROPIC_API_KEY.
const openrouter = new Anthropic({
  authToken: process.env.OPENROUTER_API_KEY,
  apiKey: null,
  baseURL: "https://openrouter.ai/api",
});

const message = await openrouter.messages.create({
  model: "anthropic/your-model-id", // an Anthropic model id from OpenRouter's model list
  max_tokens: 256,
  messages: [{ role: "user", content: "Say hello" }],
});
console.log(message.content);
```
</Tab>
</Tabs>

Streaming responses pass through as they arrive. cb scrubs every response: if the real key, or its base64 form,
ever appears in a response body, it is replaced with `[cb-redacted]`.

<Callout type="warning">
  Don't name the base URL key `OPENAI_BASE_URL` if the app also uses OpenAI. The OpenAI SDK reads that name on its
  own, and OpenAI calls would go to OpenRouter's listener.
</Callout>

## Run it

```bash
npx cb run -- npm run dev
```

If you ran `cb init`, your package scripts already run under cb. To see the stand-in values, run
`npx cb env print`. See [cb run](/docs/guides/develop/cb-run).

## Limits

- The app must send the stand-in in the `Authorization: Bearer` header, as the SDK does.
- Host redirection of `openrouter.ai` works in processes started by `cb run`. Other processes need the base URL key.
- Revoking a developer's access stops their calls; requests then get `403` with `cb_access_revoked`.

## Troubleshooting

| Problem | Fix |
|---|---|
| **Save & test** says "The API rejected the key (HTTP 401)" | The real key is wrong or disabled. Create a new key in OpenRouter and paste it again. |
| Your app gets `401` with `{"error":"cb_invalid_credential"}` | The app sent a key that isn't this device's stand-in, for example a real key from a `.env` file. Run `npx cb doctor`. |
| Your app gets `502` with `cb_upstream_unreachable` | The cb server couldn't reach OpenRouter. |

More fixes are in [Troubleshooting](/docs/guides/troubleshooting).
