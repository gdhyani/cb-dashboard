Store your real Anthropic API key in cb once. Every developer's app gets a stand-in key that starts with
`sk-ant-cb-`, and the cb gateway swaps in the real key on the way to `api.anthropic.com`. The official
`@anthropic-ai/sdk` works unchanged, including streaming.

## Before you start

- You are an owner or admin of the organization.
- You have a real Anthropic API key (`sk-ant-…`) from the Anthropic Console.
- Developers who will run the app have [access](/docs/guides/dashboard/access) to the environment.

## Add it in the dashboard

<Steps>
<Step>
### Open the Variables tab

Open your project, pick the environment, and go to the [Variables tab](/docs/guides/dashboard/variables). Click
**Anthropic** in the **Quick add** row, or click **Add variable**, set **What is this?** to **AI API key** and
**Provider** to **Anthropic**. The dialog is titled **Add AI variable**.
</Step>
<Step>
### Name the key and paste the real value

Type the **Key** your code reads, usually `ANTHROPIC_API_KEY`, and paste the real key into **API key**.
</Step>
<Step>
### Add the base URL key if your code reads one

Open **Suggested extra keys** and tick `ANTHROPIC_BASE_URL` only if your code or SDK reads a base URL. The official
SDK reads `ANTHROPIC_BASE_URL` on its own when it is set. Without it, cb still catches calls to
`api.anthropic.com` from processes started with `cb run`.
</Step>
<Step>
### Save & test

Click **Save & test**. cb calls `GET /v1/models` with the real key from its server before saving. If Anthropic
rejects the key, nothing is saved and the dialog shows the error.
</Step>
</Steps>

<Fields title="Required">
  <Field name="Key" type="text" required>
    The name your code reads, for example `ANTHROPIC_API_KEY`. cb never names it for you.
  </Field>
  <Field name="What is this?" type="select" required default="AI API key">
    The variable type.
  </Field>
  <Field name="Provider" type="select" required>
    Choose **Anthropic**.
  </Field>
  <Field name="API key" type="secret" required>
    The real key, such as `sk-ant-…`. Write-only: nobody can view it after saving, but you can replace it.
  </Field>
</Fields>

<Fields title="Optional (Advanced)" collapsible>
  <Field name="Different endpoint" type="text">
    A company proxy or another endpoint instead of the default `https://api.anthropic.com`. Must be `https://`.
    When you set it, have your app use the base URL key so its calls reach cb.
  </Field>
  <Field name="Extra headers" type="multiline">
    Non-secret headers sent on every call, one `Name: value` per line, at most 10 (for example an `anthropic-beta`
    header). Not for keys: `Authorization`, `x-api-key`, `Cookie` and transport headers are set by cb.
  </Field>
</Fields>

<Callout type="note">
  Developers get a stand-in that cb makes for each device; there is nothing to enter for it. See
  [stand-in values](/docs/overview/concepts#stand-in-values).
</Callout>

## Use it in code

Use the official SDK as you do in production. It reads `ANTHROPIC_API_KEY` and `ANTHROPIC_BASE_URL` from the
environment and sends the key in the `x-api-key` header, which is where cb expects it.

<Tabs items={["Messages", "Streaming"]}>
<Tab value="Messages">
```ts title="lib/ai.ts"
import Anthropic from "@anthropic-ai/sdk";

const anthropic = new Anthropic(); // reads ANTHROPIC_API_KEY (and ANTHROPIC_BASE_URL if set)

const message = await anthropic.messages.create({
  model: "your-model-id",
  max_tokens: 256,
  messages: [{ role: "user", content: "Say hello" }],
});
console.log(message.content);
```
</Tab>
<Tab value="Streaming">
```ts title="lib/ai-stream.ts"
import Anthropic from "@anthropic-ai/sdk";

const anthropic = new Anthropic();

const stream = anthropic.messages.stream({
  model: "your-model-id",
  max_tokens: 256,
  messages: [{ role: "user", content: "Write a haiku" }],
});
stream.on("text", (text) => process.stdout.write(text));
await stream.finalMessage();
```
</Tab>
</Tabs>

Streaming responses (server-sent events) pass through as they arrive. cb scrubs every response: if the real key, or
its base64 form, ever appears in a response body, it is replaced with `[cb-redacted]`.

## Run it

```bash
npx cb run -- npm run dev
```

If you ran `cb init`, your package scripts already run under cb. To see the stand-in values, run
`npx cb env print`. See [cb run](/docs/guides/develop/cb-run).

## Limits

- The app must send the stand-in in the `x-api-key` header, as the SDK does.
- Host redirection of `api.anthropic.com` works in processes started by `cb run`. Other processes need the base URL
  key.
- Calls go through the cb gateway, which adds a network hop between your laptop and Anthropic.
- Revoking a developer's access stops their calls; requests then get `403` with `cb_access_revoked`.

## Troubleshooting

| Problem | Fix |
|---|---|
| **Save & test** says "The API rejected the key (HTTP 401)" | The real key is wrong or disabled. Create a new key in the Anthropic Console and paste it again. |
| Your app gets `401` with `{"error":"cb_invalid_credential"}` | The app sent a key that isn't this device's stand-in, for example a real key from a `.env` file or a key in an `Authorization` header instead of `x-api-key`. Run `npx cb doctor`. |
| Your app gets `502` with `cb_upstream_unreachable` | The cb server couldn't reach Anthropic (or the **Different endpoint**). |
| Calls fail with an authentication error from Anthropic itself | The process didn't start under `cb run`. Start it with `cb run`, or add `ANTHROPIC_BASE_URL`. |

More fixes are in [Troubleshooting](/docs/guides/troubleshooting).
