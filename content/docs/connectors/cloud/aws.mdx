---
title: AWS / S3-compatible
description: Use Amazon S3, SES, Cloudflare R2 or other S3-compatible storage with the AWS SDK, presigned URLs included, without the real access keys.
---

Store your real AWS access key pair in cb once. Every developer's app gets stand-in AWS keys and a local endpoint.
The AWS SDK signs each request with the stand-in keys as usual; the cb gateway checks the signature's access key,
re-signs the request with the real keys, and sends it to the real endpoint. Presigned URLs are re-signed the same
way when they are opened.

## Before you start

- You are an owner or admin of the organization.
- You have a real access key ID (`AKIA…`) and secret access key, and the region of the service (your bucket or SES
  region).
- For Cloudflare R2, MinIO, Backblaze or other S3-compatible storage, you have the storage's S3 endpoint, for
  example `https://<account>.r2.cloudflarestorage.com`.
- Developers who will run the app have [access](/docs/guides/dashboard/access) to the environment.

<Callout type="tip">
  Give cb an access key scoped to what the app needs. A key that can only reach one bucket, or only send email, still
  passes **Save & test**: AWS checks the key's signature before it refuses the test call.
</Callout>

## Add it in the dashboard

<Steps>
<Step>
### Open the Variables tab

Open your project, pick the environment, and go to the [Variables tab](/docs/guides/dashboard/variables). Click
**AWS S3** or **Amazon SES** in the **Quick add** row, or click **Add variable** and set **What is this?** to
**AWS / S3-compatible**. The dialog is titled **Add AWS / S3-compatible variable**.
</Step>
<Step>
### Pick the service

Set **Service** to the AWS API your code calls: **Amazon S3**, **Amazon SES (email)** or
**S3-compatible (R2, MinIO, Backblaze)**. cb fills in the service's endpoint from the region and suggests the
endpoint variable that service's AWS SDK client reads. Each AWS variable serves one service; add another AWS
variable for a second service (they can use the same keys).
</Step>
<Step>
### Name the key and paste the real values

Type the **Key** for the secret key, usually `AWS_SECRET_ACCESS_KEY`, and paste the real secret into **Secret access
key**. Enter the real **Access key ID** (cb needs it to sign requests) and the **Region**.
</Step>
<Step>
### Choose the extra keys

Open **Suggested extra keys**. `AWS_ACCESS_KEY_ID` and the service's endpoint variable are ticked already. Tick
`AWS_REGION` if your code reads the region. Rename any of them to the names your code reads, for example
`SES_ACCESS_KEY_ID`.

| Service | Endpoint cb uses | Endpoint variable (ticked) |
|---|---|---|
| Amazon S3 | `https://s3.<region>.amazonaws.com` | `AWS_ENDPOINT_URL_S3` |
| Amazon SES (email) | `https://email.<region>.amazonaws.com` | `AWS_ENDPOINT_URL_SESV2` (and `AWS_ENDPOINT_URL_SES` for the classic `SESClient`, not ticked) |
| S3-compatible | the **Endpoint** you enter | `AWS_ENDPOINT_URL` |

Recent AWS SDKs read these variables on their own, so the client needs no `endpoint` option.
</Step>
<Step>
### S3-compatible storage: enter the endpoint

With **S3-compatible**, enter the storage's **Endpoint**, for example
`https://<account-id>.r2.cloudflarestorage.com` for Cloudflare R2 with the region `auto`.
</Step>
<Step>
### Save & test

Click **Save & test**. cb signs one harmless call for the service with the real keys before saving: `ListBuckets`
for S3, `GetAccount` for SES. If the key or secret is wrong, nothing is saved and the dialog
shows the error.
</Step>
</Steps>

## Use it in code

Create the client from the environment as you do in production. Recent AWS SDKs read the endpoint variable
(`AWS_ENDPOINT_URL_S3`, `AWS_ENDPOINT_URL_SESV2`, …) on their own; for S3, use path-style addressing, because the
local endpoint is an IP address that can't carry a bucket name as a subdomain.

<Tabs items={["S3", "Presigned URLs", "SES"]}>
<Tab value="S3">
```ts title="lib/storage.ts"
import { GetObjectCommand, PutObjectCommand, S3Client } from "@aws-sdk/client-s3";

// Reads AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_ENDPOINT_URL_S3 from the environment.
export const s3 = new S3Client({ region: process.env.AWS_REGION, forcePathStyle: true });

await s3.send(new PutObjectCommand({ Bucket: "uploads", Key: "hello.txt", Body: "hi" }));
const object = await s3.send(new GetObjectCommand({ Bucket: "uploads", Key: "hello.txt" }));
console.log(await object.Body?.transformToString());
```
</Tab>
<Tab value="Presigned URLs">
```ts title="lib/presign.ts"
import { GetObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";
import { s3 } from "./storage";

const url = await getSignedUrl(s3, new GetObjectCommand({ Bucket: "uploads", Key: "hello.txt" }), {
  expiresIn: 60,
});
// http://127.0.0.1:7409/uploads/hello.txt?X-Amz-Credential=AKIACB…&X-Amz-Signature=…
```

A presigned URL points at the local endpoint and carries the stand-in signature. When it is opened, cb re-signs it
with the real keys. A browser on the same machine can open it while `cb run` is running.
</Tab>
<Tab value="SES">
```ts title="lib/mail.ts"
import { SendEmailCommand, SESv2Client } from "@aws-sdk/client-sesv2";

// Service: Amazon SES. Extra keys renamed to SES_ACCESS_KEY_ID / SES_REGION; AWS_ENDPOINT_URL_SESV2 kept.
const ses = new SESv2Client({
  region: process.env.SES_REGION,
  credentials: {
    accessKeyId: process.env.SES_ACCESS_KEY_ID!,
    secretAccessKey: process.env.SES_SECRET_ACCESS_KEY!,
  },
});

await ses.send(
  new SendEmailCommand({
    FromEmailAddress: "Shop <shop@acme.example>",
    Destination: { ToAddresses: ["ada@acme.example"] },
    Content: { Simple: { Subject: { Data: "Hello" }, Body: { Text: { Data: "Hi Ada" } } } },
  }),
);
```
</Tab>
</Tabs>

<Callout type="note" title="One service per variable">
  Each AWS variable sends every request to one endpoint, so use one AWS variable per service. Two variables can hold
  the same keys, for example one for S3 and one for SES.
</Callout>

<Callout type="note" title="Verified services">
  S3 (including presigned URLs) and SES are verified end to end with real AWS. Amazon SQS is not offered for now.
</Callout>

## Run it

```bash
npx cb run -- npm run dev
```

If you ran `cb init`, your package scripts already run under cb. To see the stand-in values, run
`npx cb env print`. See [cb run](/docs/guides/develop/cb-run).

## Limits

- Your app must send requests to the local endpoint; requests straight to `amazonaws.com` are not caught.
- Presigned URLs work only on the developer's machine while `cb run` is running. Don't hand them to other people or
  devices.
- **Save & test** signs one call for the chosen service (`ListBuckets`, `GetAccount` or `ListQueues`). A key that
  isn't allowed that call still passes ("key accepted; can't list buckets"), because AWS checked the signature first;
  an unknown key ID or a wrong secret fails. For email over SMTP instead, see [SMTP](/docs/connectors/cloud/smtp).
- Plain `http://` endpoints are accepted only for private addresses, and only while the cb server allows them.
- Revoking a developer's access stops their requests.

## Troubleshooting

| Problem | Fix |
|---|---|
| **Save & test** says "Request rejected (HTTP 403 SignatureDoesNotMatch)" or "InvalidSignatureException" | The secret access key doesn't match the access key ID. Paste both again. |
| **Save & test** says "InvalidClientTokenId" or "UnrecognizedClientException" | The access key ID is unknown to AWS (deleted, or from another account). |
| SES answers `AccessDenied … not authorized to perform ses:SendEmail` | The key's IAM user may not send as that address. Allow `ses:SendEmail` on the sender identity, or use the key your production server sends with. |
| SES calls skip cb and fail with "security token is invalid" | The client didn't find cb's endpoint. `SESv2Client` reads `AWS_ENDPOINT_URL_SESV2`, the classic `SESClient` reads `AWS_ENDPOINT_URL_SES`. |
| Your app gets `403` with `cb_invalid_credential` ("AWS access key is not valid for this device") | The app signed with keys that aren't this device's stand-ins, for example real keys from a `.env` file or `~/.aws/credentials`. Pass the keys from `process.env`. |
| Requests go to a host like `uploads.127.0.0.1` | The SDK used virtual-hosted addressing. Set `forcePathStyle: true`. |
| Your app gets `502` with `cb_upstream_unreachable` | The cb server couldn't reach the endpoint. Check the **Custom endpoint**. |

More fixes are in [Troubleshooting](/docs/guides/troubleshooting).
