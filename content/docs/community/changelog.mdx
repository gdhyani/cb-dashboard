This page lists notable changes across the three cb repositories, grouped by the day they were merged, newest
first. Internal maintenance (dependency updates, CI and tooling) is left out. cb is pre-1.0, so every change lands
on `main`.

## 7 October 2026

### Dashboard

- **Drop key files.** The service-account JSON, a CA certificate (`.pem`) and an Apple `.p8` key can be dropped or
  chosen as a file instead of pasted. Wrong files are refused with the reason, never shown; files saved on Windows
  work as they are.
- **Aiven and DigitalOcean databases** open **Advanced** by themselves and ask for the provider's CA certificate.
  A stored CA is shown by its subject and expiry, with **Remove**; a new file replaces it.
- **Key status.** Every service key has a dot: green **Working**, a red **Expired** badge when the provider refuses
  the key (deleted, rotated or expired), grey **Not checked yet**. The key stays hidden in every state.
- Secret fields never offer to save in the browser's password manager, and no form can put a value in a URL.
- **Import .env** never guesses Plain for a line that looks like a secret, and can import it as **Secret shown
  as-is**. That includes secrets behind a browser prefix (`NEXT_PUBLIC_…SECRET…`), password, auth, signing and DSN
  names, and URLs that carry a password or a token. A protected key named `NEXT_PUBLIC_…` (or `VITE_…`) gets a warning.

### Backend

- **Uploaded files are stored encrypted** in a file store: the backend's database (default) or a private
  Supabase Storage bucket (`FILE_STORE=supabase`). `npm run migrate:file-store -- --apply` moves older files.
- The gateway also hides a real key that a provider echoes in a **response header**, a **redirect**, a
  **compressed** body, or **URL-encoded / JSON-escaped / Basic** form; AWS errors never show the real access key id.
- Deleting a service, an environment or a project removes everything kept for it (stored files, stand-in key
  material, swapped tokens).
- **Save & test** explains a database whose certificate is signed by a private CA.

### CLI

- `cb env print` lists the path of stand-in key files and honours `CB_SERVER_URL` like every other command.
- The agent's log and lock files are readable only by you; `Basic …` credentials are removed from its log.
- The agent ignores `SIGUSR1` and never inherits `NODE_OPTIONS`, so no other process on your machine can attach a
  debugger to it or load code into it.

## 6 October 2026

### Dashboard

- **Supabase docs** list the four values from Supabase's Connect → Server tab and which one cb protects.
- **AWS Service** offers Amazon S3, Amazon SES and S3-compatible storage. Amazon SQS is no longer offered;
  variables saved with it keep working.
- **Documentation.** The docs you are reading are now built into the dashboard at `/docs`, with local search,
  ⌘K, and links from the avatar menu, the login and sign-up pages and empty states.
- **Webhooks setup in one panel.** Connect Stripe (full, thin or both event formats) and Connect Razorpay from
  one panel, with the webhook URL, a cb-made Razorpay secret and **Send to me**.
- **New secret** is offered only for Razorpay signing secrets that cb made, and toasts can now be closed.
- The webhook URL is always visible, keys open in a read-only view, the Webhooks tab starts with setup, and
  badges use consistent colours.
- **Supabase** is its own type under Databases, with a **Quick add** chip: secret key plus Project URL, with the
  publishable key refused in the secret field.
- The webhook **App port** field is gone: cb finds the port itself. Forms check webhook paths (a single leading `/`,
  no spaces) and Stripe signing secrets (`whsec_…`) before saving, and removing a connected webhook key says what
  happens at the provider.

### Backend

- **Connect Stripe and Razorpay.** Webhook endpoints can be connected for you, with Stripe's full, thin or both
  formats; one URL serves both Stripe formats, and **Send to me** delivers a test event to your device.
- The backend records where each webhook signing secret came from.
- HTTP API keys: the device's stand-in is replaced with the real key in every header that carries it, so SDKs
  that send the key twice (Supabase) work; the Supabase preset lets its public key through unchanged.
- Verified with real providers: MongoDB Atlas (`mongodb+srv://` and replica-set URLs), Neon Postgres, Redis Cloud,
  Supabase, OpenRouter (OpenAI and Anthropic SDKs), and AWS S3 and SES.

### CLI

- Webhooks are delivered to the port your app really listens on, and wait while the app starts.
- After an upgrade, `cb` replaces an older background agent automatically.

## 5 October 2026

### Dashboard

- **Variables tab.** One place to add and manage keys: a quick-add row, one **Add variable** dialog with type,
  provider, extra keys and **Advanced** settings, keys grouped under their service, and a connection map. The
  separate Resources tab is gone.
- **Edit a variable.** Rename it, replace its value (tested before it is stored) or change its settings.
- **Import .env**, Google service-account key files, and a CA certificate and extra headers for API services.
- **Webhook signing secret** type and a **Webhooks** tab.
- **Who can use it**: choose per key which login it uses.
- The dashboard now says *service* instead of *resource*; extra key names stay readable on phones.

### Backend

- **Webhooks.** A central webhook address for each project, routed to the right developer and delivered reliably
  to each device.
- **One-step service setup.** Adding a key with its service is a single request that tests the credential first
  and saves nothing if the test fails.
- **New AI providers:** Gemini, Groq, Mistral and OpenRouter, grouped under one AI type.
- API keys can be sent in a named header; plain variables can link to a service.
- Plain `http://` upstreams are allowed only for private addresses, with a switch for local development.
- Google key files, and a CA certificate plus extra headers for API services.
- Removing or disabling a service closes live connections within five seconds.
- The connection test calls an authenticated path, so **Save & test** rejects a wrong API key.
- A migration brings existing services into the new Variables format.
- Fixes: MongoDB SCRAM-SHA-1 and SCRAM-SHA-256 negotiation upstream; MySQL connection tests decide TLS from the
  URI like the gateway; one webhook stream per device.

### CLI

- **Webhooks delivered to your app,** with an event stream that stays up for days.
- Stand-in key files for `GOOGLE_APPLICATION_CREDENTIALS`.
- `cb run`, the agent and `cb types` now honour `CB_SERVER_URL` over the project's saved server.

## 4 October 2026

The first public versions of all three repositories.

### Dashboard

- Sign up, log in, and approve CLI devices.
- Projects, environments and members, with a project switcher in the navbar and access flows for projects,
  environments and people, including an access preview.
- Provider presets with **Test connection**, and CA certificates for self-hosted and private-CA servers.
- **Emergency stop**, and the **Devices & sessions** pages.

### Backend

- The REST API and the credential gateway, with adapters for PostgreSQL, MySQL, MongoDB, Redis, SMTP and HTTP
  providers.
- Access and refresh tokens with reuse detection.
- Project-wide access and per-person project access.
- Provider presets and connection tests.
- Kill switches, sessions and agent heartbeat.
- Per-request routing for providers that share a host.
- MongoDB `mongodb+srv://` and replica-set URIs; verified TLS to MySQL; per-service CA certificates for
  self-hosted databases.
- Revoked connections fail with each protocol's own error.

### CLI

- `cb login`, `cb init` and `cb run`, with the background agent, the preload and the operating system keychain.
- `cb shell`, `cb types`, `cb doctor`, `cb up` / `cb down` and the explicit `env` API.
- `cb run` refuses to start while access is stopped, and the agent reacts to the emergency stop.
- Tested on Linux, macOS and Windows.
